## Work

Created `packages/squad-sdk/src/skills/skill-script-loader.ts` — SkillScriptLoader class for dynamic loading of executable skill handlers from backend skill directories (`.squad/skills/{name}/scripts/`).

**Key deliverables:**
- SkillScriptLoader class with load() method
- resolveSkillPath() utility for path containment enforcement
- wrapSkillHandler() bridge from SkillHandler to SquadToolHandler signature
- Added `ToolRegistry.applySkillHandlers()` method in `packages/squad-sdk/src/tools/index.ts`
- Updated exports in `packages/squad-sdk/src/skills/index.ts`

**Key design decisions:**
1. Tool name → script name mapping: `squad_create_issue` → `create_issue.js`
2. Windows path normalization before pathToFileURL() conversion
3. Path containment enforcement: resolved paths must stay within projectRoot or teamRoot
4. Partial implementation support: missing scripts skipped, invalid exports fatal
5. Optional lifecycle hooks support (init, dispose)
6. ToolRegistry integration: post-construction handler swaps only

## Decision

Wrote decision: `.squad/decisions/inbox/eecom-skill-script-loader.md`

**Summary:** SkillScriptLoader enables backend skills to replace built-in tool handlers. Design prioritizes security (path containment), partial implementations, and Windows compatibility. ToolRegistry remains single source of truth.
